# PingDeck 多语言适配设计

- 日期：2026-11-06
- 状态：已确认，待实现
- 分支：`feat/i18n`

## 1. 背景与目标

PingDeck 目前所有界面文案、核心错误信息与导出内容都硬编码为简体中文。本设计引入多语言支持，目标如下：

- 首批支持简体中文、English、日本語。
- 界面、菜单、对话框、校验/导入错误、导出表头与摘要跟随应用语言。
- 使用 Apple 官方 i18n 体系，不自研运行时字符串表。
- 不改变 JSON 导出的机器可读 schema；JSON 字段名与状态值保持英文。
- 保持 PingCore 的界面无关性：核心逻辑只返回类型化结果，文案由 UI 层负责。

## 2. 关键决策

| 决策项 | 结论 |
| --- | --- |
| 首批语言 | `zh-Hans`、`en`、`ja` |
| 兜底语言 | `en`；系统语言不在支持列表时回落英文 |
| 切换方式 | 默认跟随系统；设置内可手动指定；重启后生效 |
| 本地化范围 | 界面 + 导出内容；README 与文档不翻译 |
| 资源位置 | String Catalog 只放在 `PingDeck` target；PingCore 不依赖展示资源 |
| 核心层改造 | 校验、导入、引擎错误改为类型化枚举；导出通过 `ExportLabels` 注入文案 |
| 翻译来源 | 现有简体中文作为源文案；English / 日本語由用户提供 |

### 2.1 语言查找行为

- String Catalog 的 `sourceLanguage` 为 `zh-Hans`，现有中文文案即源文案。
- `Package.swift` 的 `defaultLocalization` 为 `en`，生成的资源 bundle 开发区域为 `en`。
- 系统语言为 `en` / `ja` / `zh-Hans` 时使用对应本地化；其它语言回落 `en`。
- 已在隔离探针中验证：该组合下系统语言为 `fr` 时正确回落英文。

## 3. 技术方案

### 3.1 String Catalog 与类型安全符号

资源文件：

```text
Sources/PingDeck/Resources/Localizable.xcstrings
```

Catalog 约定：

- 所有 key 使用 `extractionState: manual`，每个 key 必须写 `comment` 说明使用场景。
- key 采用 `<区域>.<元素>[.<状态>]` 的语义化命名，例如：
  - `toolbar.add`
  - `settings.language.restartHint`
  - `status.timeout`
  - `alert.import.completed`
  - `export.column.lastLatency`
- 插值使用格式占位符；多参数时使用位置参数，允许不同语言调整语序：
  - 整数：`%lld`，如 `%1$lld`
  - 字符串：`%@`，如 `%1$@`
  - 小数：`%.1f`
- 能写成中性文案的地方优先中性文案，避免英语复数变化。例如状态栏使用 `Targets: %lld`，而不是 `1 target / 2 targets`。
- 无法避免复数变化时，使用 String Catalog 原生 `plural` variations；中日文只提供 `other`。
- 不进入 Catalog 的内容：
  - 品牌名 `PingDeck`
  - 格式名 `CSV`、`JSON`、`TXT`、`Markdown`、`Excel (XLSX)`
  - IP/域名示例、文件扩展名
  - 来自 `ping` 进程的原始输出文本

SwiftPM 会为 manual 条目生成类型安全符号，但在 `swift test` 重新编译可执行 target 时不会包含该生成文件。因此项目使用 `xcstringstool` 显式生成 `L10n` 命名空间并纳入源码：

```bash
scripts/generate-localization-symbols.sh
```

生成结果位于 `Sources/PingDeck/Generated/L10n.swift`。界面与 Foundation 层使用：

```swift
Text(L10n.settingsTitle)
String(localized: L10n.alertTargetsAddedTitle(count))
```

修改 Catalog 后必须重新运行生成脚本。`L10n` 是 `internal`，只在 `PingDeck` 模块内使用。因此 Catalog 必须留在 `PingDeck` target，PingCore 不得引用这些符号。

### 3.2 PingCore 类型化边界

PingCore 不再返回面向用户的中文字符串，只返回可判定的枚举与数据。

#### 目标校验

```swift
public enum TargetValidationIssue: Equatable, Sendable {
    case empty
    case protocolPrefix
    case path
    case whitespace
    case invalidCharacters
}

public enum TargetValidator {
    public static func validate(_ host: String) -> TargetValidationIssue?
}
```

#### 网段解析与批量导入

```swift
public enum IPv4RangeError: Equatable, Sendable {
    case ipv6Unsupported
    case malformedCIDR
    case cidrNotNetworkAddress
    case rangeTooLarge(limit: Int)
    case malformedRange
    case endBeforeStart
}

public enum RejectionReason: Equatable, Sendable {
    case duplicate
    case invalidTarget(TargetValidationIssue)
    case invalidRange(IPv4RangeError)
}
```

- `IPv4Range.ParseResult.invalid` 携带 `IPv4RangeError`。
- `BulkImportParser.Rejected.reason` 改为 `RejectionReason`。
- 两处完全相同的“网段格式不正确：请写成…”合并为 `.malformedRange`。

#### 进程与引擎错误

```swift
public enum PingProcessError: Error, Equatable, Sendable, Codable {
    case executableNotFound(path: String)
    case launchFailed(message: String)
}

public enum PingStatusDetail: Equatable, Sendable, Codable {
    case disabled
    case launchFailed(host: String, error: PingProcessError)
    case processExited(code: Int32)
}

public enum PingEngineIssue: Equatable, Sendable {
    case launchFailed(host: String, error: PingProcessError)
}
```

- `PingProcess.start()` 找不到 ping 时抛 `.executableNotFound`；`Process.run()` 失败包装为 `.launchFailed(message:)`。
- `PingStats` 新增 `detail: PingStatusDetail?`：
  - 停用目标：`detail = .disabled`，不再写入中文字符串。
  - 启动失败：`detail = .launchFailed(...)`。
  - 进程异常退出：`detail = .processExited(code:)`。
  - 成功响应时清除 `detail` 与 `message`。
- `PingStats.message` 保留给 `ping` 原始输出（不可达/失败文本），不翻译。
- `PingEngine.onError` 改为 `((PingEngineIssue) -> Void)?`，`PingEngineIssue.launchFailed(host:error:)` 由 ViewModel 本地化后展示。

UI 展示优先级：`detail` 本地化文案 → `message` 原始文本 → `TargetStatus` 本地化名称。

#### 移到 UI 层的展示逻辑

- `TargetStatus.displayName`：删除，改为 `PingDeck` 内的扩展，映射到 `status.*`。
- `AppearanceMode.displayName`：删除，改为 `PingDeck` 内的扩展，映射到 `appearance.*`。
- `ImportMode.title`、`ExportFormat.displayName` 等纯展示属性保持在 UI 层或使用固定名称。

### 3.3 导出标签注入

```swift
public struct ExportLabels {
    public var columnTitles: [String]
    public var statusName: (TargetStatus) -> String
    public var summary: (ExportSummary) -> String
    public var markdownTitle: String
    public var exportedAtLabel: String
}
```

- `ExportTable(entries:labels:)`：列标题来自 `labels.columnTitles`，数量必须与列定义一致。
- `ExportValueFormatter.display(_:format:labels:)`：状态名来自 `labels.statusName`。
- `CsvExporter.csv(for:labels:)`、`TextExporter.text(for:labels:)`、`XlsxExporter.xlsx(for:labels:)`、`MarkdownExporter.markdown(for:exportedAt:labels:)` 接收标签。
- `ExportFile.data(format:entries:date:labels:)` 由 `ContentView` 传入本地化标签。
- `JsonExporter` 不接收标签：字段名、状态枚举值、汇总 key 保持英文。
- 日期格式保持 `yyyy-MM-dd HH:mm:ss`，不随语言变化，保证 CSV 兼容与跨工具可读。
- 删除 `CsvExporter.header` 静态属性；测试改用 `ExportTable(entries:labels:).columns.map(\.title)`。

### 3.4 语言设置与启动应用

```swift
public enum AppLanguage: String, Codable, CaseIterable, Sendable {
    case system
    case simplifiedChinese = "zh-Hans"
    case english = "en"
    case japanese = "ja"

    public var localeIdentifier: String? { self == .system ? nil : rawValue }
}
```

- `PingSettings` 新增 `language: AppLanguage = .system`。
- 解码时缺失或未知值回落 `.system`，确保旧配置不会整体解码失败。
- 设置页新增“语言”选择：
  - 跟随系统（本地化）
  - 简体中文、English、日本語（使用 `Text(verbatim:)`，语言名称不翻译）
- 选择后：
  1. 更新 `settings.language` 并保存配置；
  2. 写入/清除 `AppleLanguages`；
  3. 显示“重启后生效”提示。
- `LanguagePreference`（`PingDeck` 内部）：

```swift
enum LanguagePreference {
    static let appleLanguagesKey = "AppleLanguages"

    static func apply(_ language: AppLanguage, defaults: UserDefaults = .standard) {
        switch language {
        case .system:
            defaults.removeObject(forKey: appleLanguagesKey)
        case .simplifiedChinese, .english, .japanese:
            defaults.set([language.rawValue], forKey: appleLanguagesKey)
        }
    }
}
```

- `AppDelegate.applicationWillFinishLaunching` 读取配置并调用 `LanguagePreference.apply`，确保 App 菜单与界面在首次绘制前使用正确语言。
- 应用内选择优先于 macOS“按应用设置语言”；选择“跟随系统”时移除应用级覆盖，交回系统。

### 3.5 打包

`Package.swift`：

```swift
let package = Package(
    name: "PingDeck",
    defaultLocalization: "en",
    ...
    .executableTarget(
        name: "PingDeck",
        dependencies: ["PingCore"],
        resources: [.process("Resources")]
    )
)
```

`scripts/bundle.sh`：

1. 从可执行文件所在目录查找 SwiftPM 生成的资源 bundle（当前预期名为 `PingDeck_PingDeck.bundle`）。
2. 复制到 `PingDeck.app/Contents/Resources/`。
3. 先对资源 bundle 签名，再对 `.app` 签名：
   - 正式证书：`--options runtime --timestamp`
   - 本地：ad-hoc
4. `Info.plist` 增加：

```xml
<key>CFBundleDevelopmentRegion</key>
<string>en</string>
<key>CFBundleLocalizations</key>
<array>
    <string>en</string>
    <string>zh-Hans</string>
    <string>ja</string>
</array>
```

资源 bundle 不存在时构建必须失败，避免产出无本地化资源的 App。

## 4. 数据模型与兼容性

`PingSettings`：

```swift
public var language: AppLanguage
```

- 新增 `CodingKeys.language`。
- 自定义 `init(from:)` 中用 `decodeIfPresent`，失败回落 `.system`。
- `encode(to:)` 使用合成实现，旧版本读取新增字段时忽略即可。

`AppConfiguration` 结构不变。

`PingStats` 新增 `detail`：

- `PingStats` 为 `Codable`，`PingStatusDetail` 与 `PingProcessError` 同时实现 `Codable`。
- `detail` 为可选字段，旧数据缺失时解码为 `nil`。
- 统计结果不写入配置文件，兼容风险仅限于测试/内存数据。

## 5. 文案迁移与翻译交付

### 5.1 迁移规则

- SwiftUI 文案使用 `Text(.key)`；`Label`、`Button` 标题使用本地化资源。
- 表格列标题、排序菜单、工具栏提示统一改为 Catalog key；`TargetColumn.title` 不再硬编码中文。
- 拼接字符串（如“第 N 行「内容」：原因”）改为 Catalog 插值 key，不在代码中拼中文。
- 可翻译的 `String` 属性（错误、状态、提示）改为类型化枚举 + UI 扩展。
- 除注释与 Catalog 外，`Sources/` 中不再出现面向用户的中文字面量。
- `Text(verbatim:)` 仅用于 IP、域名、数字、语言自称等不可翻译内容。

### 5.2 翻译清单

实现前生成一份清单，列：

```text
key | zh-Hans（现有文案） | en | ja | comment
```

- 用户补全 `en` 与 `ja` 两列。
- 合并进 `Localizable.xcstrings` 后，Catalog 成为唯一事实来源。
- 清单是临时交付物，不提交到仓库，避免与 Catalog 漂移。

### 5.3 质量门槛

新增测试解析 `Localizable.xcstrings`，校验：

1. `sourceLanguage == "zh-Hans"`。
2. 每个 key 都有 `en`、`zh-Hans`、`ja` 三个本地化，且值非空。
3. 每个 key 都有非空 `comment`。
4. 同一 key 各语言的格式占位符集合一致；多参数使用位置参数。
5. 使用 `plural` variations 的 key，各语言包含完整类别。

该测试是合并前的硬性门槛。

## 6. 测试策略

### 6.1 核心层

- `TargetValidator`：断言 `TargetValidationIssue` 枚举值。
- `BulkImport` / `IPRangeImport`：断言 `RejectionReason` 枚举值，例如 `.duplicate`、`.invalidRange(.cidrNotNetworkAddress)`、`.invalidRange(.rangeTooLarge(limit: 1024))`。
- `PingEngine`：断言 `PingStats.detail` 的枚举值；不再断言中文字符串。
- `PingSettings`：新增语言字段的编码/解码、旧配置缺失字段回落 `.system`。
- `AppearanceTests` 中的展示名断言移除；外观模式只保留原始值/Codable 测试，展示名由 UI 层负责。

### 6.2 导出

- 测试提供固定的 `ExportLabels` fixture，保持现有中文 CSV 输出逐字节不变。
- 另加一组英文 fixture，验证表头、状态名、Markdown 标题与摘要随标签变化。
- JSON 测试保持不变，确认 schema 未受影响。

### 6.3 界面与语言偏好

- `LanguagePreference` 使用注入的 `UserDefaults(suiteName:)`：
  - 选择英文写入 `["en"]`；
  - 选择日文写入 `["ja"]`；
  - 选择跟随系统移除 `AppleLanguages`。
- Catalog 覆盖率测试（见 5.3）。
- `AppLanguage` 原始值与 Codable 测试。

### 6.4 手工验证

1. `swift build`、`swift test`。
2. `swift build -c release && scripts/bundle.sh`，确认资源 bundle 被复制且签名通过。
3. 分别以三种语言启动 App：

```bash
open dist/PingDeck.app --args -AppleLanguages '(en)'
open dist/PingDeck.app --args -AppleLanguages '(ja)'
open dist/PingDeck.app --args -AppleLanguages '(zh-Hans)'
```

或以构建产物直接运行。检查：

- 主窗口、工具栏、表头、状态栏、设置、编辑/批量导入弹窗；
- App 菜单中的“设置…”与系统菜单项；
- 错误提示、导入拒绝原因；
- CSV / TXT / Markdown / XLSX 表头与状态名；
- JSON 字段名与状态值保持英文。

4. 设置页切换语言，确认提示“重启后生效”；重启后界面与菜单一致。
5. 英文/日文下检查固定宽度布局：
   - 设置 sheet（440）
   - 目标编辑 sheet（420）
   - 批量导入 sheet（540）
   - 工具栏按钮与表头
   出现截断时调整宽度或允许换行。

## 7. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| SwiftPM 自动生成符号依赖 Xcode 工具链 | 本地 Swift 6.4 已验证；CI `macos-latest` 同属 Xcode 工具链。PR 首轮 CI 必须确认通过 |
| 生成的符号是 internal | Catalog 固定在 `PingDeck` target；PingCore 通过类型化边界保持独立 |
| 翻译缺失导致英文/日文回落中文 | 覆盖率测试作为合并门槛；翻译未齐不合并 |
| 英文/日文文案更长导致布局截断 | 三种语言下手工截图检查；必要时放宽 sheet 宽度或允许换行 |
| 嵌套资源 bundle 影响签名/公证 | `bundle.sh` 先签资源 bundle 再签 App；CI 公证流程验证 |
| 应用内语言与系统“按应用设置语言”冲突 | 应用内选择写入同一 `AppleLanguages` 域；选“跟随系统”时移除覆盖，行为明确 |
| `PingStats` 新增 `Codable` 字段 | 可选字段 + 默认 nil；不写入配置文件，旧数据兼容 |

## 8. 范围外

- 繁体中文、韩语、德语、法语、西班牙语等后续语言。
- 应用内即时切换（本轮统一重启生效）。
- README、CONTRIBUTING、DEVELOPMENT 等文档翻译。
- `ping` 原始输出的翻译。
- 日期、数字的本地化格式调整；导出时间保持固定格式。
- 导出文件名的本地化。

## 9. 实施顺序

1. 提取全部用户可见文案，生成翻译清单交给用户补全 `en` / `ja`。
2. 建立 Catalog、Package 资源与打包流程，验证自动生成符号可编译。
3. 完成 PingCore 类型化改造与测试更新。
4. 完成 UI 层 Catalog 迁移与导出标签接入。
5. 实现语言设置、启动应用与偏好测试。
6. 合并用户提供的翻译，跑覆盖率测试。
7. 三语言手工验证、打包与签名检查，提交 PR。
